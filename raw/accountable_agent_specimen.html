BOUNDARY— protocols open a new aperture into agent systems

Protocols create a new aperture into agent systems — discovery, skills, and tools become visible at the seam.

A2A gives agents a way to discover each other and coordinate tasks. MCP gives agents a practical way to call tools and access external systems. Together, they make the boundary visible.

A2A

Agent-to-agent

Remote agent discovery, skill declaration, messages, tasks, artifacts, and collaboration across agent boundaries.

MCP

Tools & resources

Tool, resource, and prompt exposure. The agent can reach into practical external systems.

GAP

The opening

The protocols do not specify how the remote agent internally remains accountable while acting.

The boundary is now protocolized. The inner body is still an architectural choice.

Cycle 1 — crystallize // first claim
CLAIM I— protocols connect agents; substrates make them accountable

First claim: protocols connect agents, but substrates make them accountable.

A2A and MCP solve crucial boundary problems. The next layer is the accountable body that makes each boundary event traceable, assessable, and governable.

DO NOT

Hide the body

Capabilities should be declared and governed, not buried in a single orchestration prompt.

DO NOT

Trust the artifact alone

A returned result must still be locally assessed before it becomes a committed fact.

DO NOT

Add audit later

The write path is the moment to enforce provenance, authority, and residual capture.

TransitionOnce the boundary event enters the body, we need a place where all transformations can meet without becoming one mutable memory.

Cycle 2 — observe // memory drifts
SUBSTRATE— inside the agent, "memory" is too vague to be the foundation

Inside the agent, "memory" is too vague to be the foundation.

Agents tend to accumulate vector stores, caches, scratchpads, task queues, graph tables, and audit logs. The more capable the system becomes, the more dangerous this drift gets.

DRIFT

State drifts

The graph says one thing, the trace says another, and the task queue has its own truth.

LEAK

Context leaks

Prompts silently carry data that was never made accountable as an input.

LATE

Audit arrives late

Logging after action cannot prove why the action had authority to happen.

The foundation should not be memory. It should be a shared information substrate.

Cycle 3 — observe // the unit question
UNIT OF WORK— a tool call is too small to be the architectural unit

A tool call is too small to be the unit of agent architecture.

The visible action may be a model call, function call, MCP tool, human review, or remote A2A task. But the meaningful architectural unit is larger.

SELECT

Selection

What was allowed into the local shell?

EXECUTE

Execution

Who or what performed the transformation?

JUDGE

Judgment

Why did the system accept, retry, ask, escalate, or abort?

The unit is not "call the tool". The unit is "transform a scoped projection and decide what may happen next".

Cycle 4 — observe // deficits as openings
DEFICIT— deficits create routes the original workflow did not draw

Deficits create routes the original workflow did not draw.

A capable agent will encounter missing sources, conflicting evidence, insufficient authority, novelty, and unclear user intent. The question is not whether this happens. The question is how the system handles it.

STATIC

Static workflows stop

If the path was not drawn, the system either fails or improvises invisibly.

UNBOUND

Unbounded agents drift

If every deficit becomes unrestricted exploration, the system loses control.

BOUNDED

Bounded agents ask

The deficit becomes a logged question routed through explicit controls.

A question is not merely clarification. It is a controlled way to open a new route.

Claims to take away // for AI engineering teams
FIVE CLAIMS— conclusions that crystallize from the cycles

Five practical claims for AI engineering teams.

CLAIM I

Protocols are boundaries

A2A and MCP are necessary, but they do not define the internal body of the agent.

CLAIM II

Trace should be substrate

Do not synchronize logs with data. Build projections from an append-only entry history.

CLAIM III

Capabilities are vessels

Every capability should resolve, act, assess, and post through one contract.

CLAIM IV

Questions are architecture

A question is a first-class way to route deficits, not a hidden model thought.

CLAIM V

Generated output is liability

A model result is useful, but it is not a committed fact until sourced, validated, or decided.

RULE

Operating rule

Let the system discover a path while every move remains bounded, inspectable, and accountable.

ANCHORS
Grounding notes // technical anchors behind the lens
ANCHORS— algebra · topology · structural information systems

Technical anchors behind the lens.

I · ALGEBRA

Algebra

Typed operators. A vessel behaves like an operator from selected inputs to posted outputs.

Composition. Operators compose only when schemas, authority, and side effects are explicit.

Differential. Assess compares intended, selected, produced, authorized, and residual state.

Liability. Generated content is a pending obligation, not a conserved fact.

II · TOPOLOGY

Topology

Local charts. Each execution shell is a local projection over the shared substrate.

Neighborhoods. Selectors define which part of the graph is visible from the current center.

Edges. Questions create new routes in the work graph.

Back-edges. Retry is allowed only with a progress measure or escalation.

III · SYSTEMS

Structural information systems

Event sourcing. Immutable entries first, read models second.

CQRS. Write model and read projections serve different purposes.

Blackboard systems. Capabilities coordinate through shared structured memory.

Data provenance. Derivation edges make lineage inspectable.
